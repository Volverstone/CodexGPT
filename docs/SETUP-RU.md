# Один журнал на компьютере, Android и iPhone

Сайт уже умеет входить в Supabase и сохранять общий журнал. Для настоящей синхронизации подключите свой проект: без URL и публичного ключа сборка продолжает работать только локально. Создать облачный проект и включить GitHub в вашем Netlify нужно в ваших аккаунтах; код сам не создаёт эти сервисы.

## 1. Создайте базу Supabase

1. Откройте https://supabase.com/dashboard и создайте проект (New project). Выберите подходящий регион. Пароль базы храните у себя, сайту он не нужен.
2. Дождитесь готовности проекта, откройте **SQL Editor → New query**.
3. В GitHub откройте [supabase/schema.sql](../supabase/schema.sql), скопируйте весь SQL, вставьте в редактор и нажмите **Run**.
4. В Table Editor появятся таблицы:

| Таблица | Что хранит |
| --- | --- |
| `students` | Имя, группа, телефон, дата присоединения, депозит |
| `attendance` | Ученик, дата занятия, статус присутствия |
| `journals` | Владелец журнала и версия для защиты от одновременной перезаписи |

Группы пока хранятся простым текстом в карточке ученика, без отдельного справочника. Пользователи и пароли обслуживаются Supabase Auth. У каждого аккаунта свой журнал. Сайт получает доступ только к журналу вошедшего пользователя (RLS); публичный ключ сам по себе не даёт доступ к ученикам. Все изменения выполняются транзакционно, через две функции `load_journal` и `save_journal`.

Это простая схема для небольшого журнала: сайт передаёт его целиком, база раскладывает данные в SQL-таблицы. С ростом данных до больших объёмов можно перейти к отдельным операциям по строкам, не меняя выбранный PostgreSQL.

## 2. Подключите GitHub к существующему сайту Netlify

ZIP-загрузка — ручной снимок сайта. Для автоматического обновления используйте Git:

1. В панели **того же проекта Netlify** откройте **Project configuration → Build & deploy → Continuous deployment → Repository**.
2. Нажмите **Link repository / Link site to Git**, выберите GitHub и `Volverstone/CodexGPT`. Разрешите Netlify доступ к этому репозиторию.
3. Ветка: **main**. Команда сборки: **npm run build**. Папка публикации (Publish directory): **dist**. Эти значения уже записаны в `netlify.toml`.
4. Если названия меню в вашей версии отличаются, ищите подключение Git-репозитория в настройках сборки. Не загружайте исходники ZIP как замену подключению Git.

Используйте существующий проект, чтобы сохранить знакомый HTTPS-адрес. Ни платная защита сайта, ни Netlify AI-агент для этой настройки не нужны.

## 3. Укажите два публичных параметра

В Supabase найдите **Project URL** (обычно `https://идентификатор.supabase.co`) и **Publishable key** в настройках проекта/API Keys или в окне **Connect**. В старом интерфейсе подходит публичный ключ **anon**.

В Netlify: **Project configuration → Environment variables → Add a variable**. Добавьте:

| Имя | Значение |
| --- | --- |
| `SUPABASE_URL` | Project URL вашего Supabase |
| `SUPABASE_PUBLISHABLE_KEY` | Публичный `sb_publishable_…` или старый anon-ключ |

Параметры должны быть доступны **при сборке (Builds)** для **Production**. Если включаете превью сборок, задайте им нужный проект отдельно.

Эти два значения используются браузером и будут видны в коде сайта — это штатно. **Не используйте `service_role`, `sb_secret_…`, пароль базы или личный access token.** Сборка отклоняет приватные ключи.

Затем откройте **Deploys → Trigger deploy → Deploy site**. После изменения переменных обязательно нужна новая сборка: уже опубликованный HTML их не читает динамически.

Готовые ZIP в GitHub по умолчанию собраны **без вашей базы**. Настройки Netlify применяются только при сборке из Git, а не при ручной загрузке готового архива.

## 4. Настройте вход и создайте один аккаунт

1. В Supabase откройте **Authentication → URL Configuration**. В **Site URL** укажите HTTPS-адрес вашего сайта Netlify. Добавьте этот же адрес в разрешённые Redirect URLs, если требуется интерфейсом.
2. Убедитесь, что вход по Email разрешён (**Authentication → Sign In / Providers → Email**).
3. На сайте нажмите **Вход и синхронизация → Создать аккаунт**. Используйте свой email и пароль не короче 8 символов.
4. Если Supabase отправил письмо подтверждения, подтвердите email, затем вернитесь на сайт и войдите с паролем. Если письма не приходят, проверьте настройки отправки/лимиты Supabase; не создавайте публичную базу без входа.
5. На компьютере, Android и iPhone войдите **в один и тот же аккаунт**. Два разных email создают два разных журнала.

Если регистрация на сайте не нужна, владелец может создать пользователя через Supabase **Authentication → Users → Add user**, а затем отключить новые регистрации. Не пересылайте пароли и токены в чат или репозиторий.

## 5. Перенесите старые записи один раз

До первого входа экспортируйте локальный журнал на устройстве, где уже есть записи. Затем войдите в аккаунт и импортируйте эту копию. Подтвердите замену общего журнала. Другие устройства увидят его после обновления.

**Импорт заменяет журнал, а не объединяет его.** Если вы уже заполнили разные данные на двух устройствах, сначала сохраните обе копии и определите, какие записи переносить. Приложение не загружает старые локальные записи в базу автоматически и не стирает их при первом входе.

## 6. Проверьте синхронизацию

1. Войдите в один аккаунт на компьютере и телефоне.
2. Добавьте ученика на компьютере. Дождитесь надписи **Сохранено в общей базе**.
3. На телефоне нажмите **Обновить** или подождите до 10 секунд при открытом приложении.
4. На телефоне поставьте посещаемость или измените депозит; проверьте изменение на компьютере.

Автопроверка выполняется каждые 10 секунд и при возвращении во вкладку. При открытой карточке, подтверждении или окне аккаунта автоматическое обновление приостановлено, чтобы не мешать редактированию. После закрытия окна можно нажать «Обновить».

Если два устройства одновременно меняют устаревшую версию, второе сохранение отклоняется, а не затирает первый результат. Закройте карточку, обновите журнал и повторите нужное изменение. При потере ответа сервера сначала обновите журнал и проверьте, не сохранилась ли запись уже.

Облачные изменения требуют интернета: без сети сайт не выдаёт ложное сообщение об успешном сохранении и не копит скрытую очередь изменений. Офлайн может открыться оболочка сайта, но загрузка общего журнала и запись в SQL-базу потребуют подключения.

## 7. Обновления сайта и базы — разные процессы

- **Записи учеников:** сохраняются сразу в Supabase. Netlify пересобирать не требуется.
- **Код и внешний вид:** изменения в GitHub/main запускают сборку Netlify. Записи в базе сохраняются независимо от новой версии сайта.
- **URL или ключ Supabase в Netlify:** после изменения нужна повторная сборка. Не переключайте проект базы, если хотите сохранить общий журнал.
- **Структура таблиц:** новые SQL-миграции применяются отдельно в Supabase SQL Editor. Netlify не должен запускать SQL с административным паролем из браузера. Текущий schema.sql можно повторить без удаления существующих журналов; это не универсальная миграция для будущих изменений.
- **Настройки аккаунта Netlify** (домен, сборка): не являются частью журнала и не копируются в БД.

## 8. Установите значок на любое устройство

- **Android:** откройте HTTPS-сайт в Chrome → **⋮ → Добавить на главный экран / Установить приложение**.
- **iPhone/iPad:** откройте тот же сайт в Safari → **Поделиться → На экран «Домой» / Добавить на экран «Домой»**.
- **Компьютер:** сайт работает в браузере. В Chrome/Edge можно выбрать установку приложения, если браузер предлагает её.

Это одно веб-приложение (PWA). APK и App Store для такого доступа не нужны. На всех устройствах используйте один аккаунт. Интерфейс адаптирован под телефон; физические Android/iPhone и Safari в этой среде не проверялись.
