# Календарь, помесячные пополнения и темы

Публикация этой версии в GitHub одобрена пользователем. Настоящая база обновляется отдельно через SQL Editor владельцем проекта.

`npm run preview` собирает `preview-calendar.html`: автономный интерактивный просмотр с вымышленными учениками. Все изменения демо живут в памяти страницы; после перезагрузки демо сбрасывается. Облачных запросов нет. Откройте файл во внутреннем просмотре HTML или полноценном браузере.

## Поведение

- По умолчанию: лекции во вторник, четверг, субботу; практика в понедельник и среду. Пятница и воскресенье — без занятий.
- «Настроить дни недели» изменяет повторяющееся расписание. В один день допускаются лекция и практика.
- «Изменить этот день» задаёт исключение на выбранную дату. Обе галочки сняты — выходной. «Вернуть недельное расписание» удаляет исключение.
- Зелёная точка в календаре — лекция, фиолетовая — практика. Особые даты отмечены дополнительной точкой в углу.
- Вкладки «Лекция» / «Практика» имеют независимые отметки даже на одной дате.
- Карточки статистики показывают конкретную дату и тип занятия; counts относятся к выбранному занятию.
- Изменение расписания не стирает старые отметки: убранное занятие остаётся доступным с пометкой «есть отметки».
- Старые записи v1 не имели типа занятия. Они сохраняются во вкладке «Прежние отметки», без догадок, было ли это практикой или лекцией. Импорт старых резервных копий поддерживается.
- Недельное расписание, исключения и отметки входят в один синхронизируемый журнал и резервную копию.

## Публикация только после одобрения

Для облачной версии сначала подготовьте резервную копию рабочего журнала. После согласования потребуется согласованное обновление приложения и SQL:

1. В Supabase SQL Editor выполнить целиком `supabase/migrations/003_monthly_deposits.sql`. Скрипт добавляет расписание, тип занятия и помесячные пополнения, сохраняет существующие данные и переносит прежние отметки в `legacy`.
2. Опубликовать согласованный код и дождаться сборки Netlify.
3. Обновить страницы на устройствах. Старый клиент v1 больше не совместим с новым форматом и не должен продолжать запись. Возможен короткий перерыв между миграцией SQL и публикацией нового сайта.

Новая версия клиента покажет прежний журнал только для просмотра и откажется сохранять данные в старую SQL-схему с понятным сообщением и ссылкой на SQL-обновление. Новая база отвергает v1-запись до изменения строк. Это предотвращает потерю расписания и разделённых отметок при смешивании версий.

Ни миграция настоящей базы, ни публикация не выполнялись при подготовке этого просмотра.

## Пополнения по месяцам

Состояние v3 хранит `deposits[YYYY-MM][studentId] = true`, отдельно от карточки ученика. В PostgreSQL используется таблица `deposits` с ключом (user_id, payment_month, student_id). Оплата августа не действует в сентябре, смена года тоже учитывается. Счётчик, фильтры, таблица и чекбокс карточки используют месяц выбранной даты; саму дату можно менять и в разделе «Ученики».

Прежний флаг students.deposit сохранён только как недатированная историческая отметка. Он не присваивается текущему месяцу при миграции; в статистике выводится число таких прежних отметок. Для переноса выберите известный месяц и отметьте пополнение заново. Удаление ученика удаляет и его помесячные отметки, изменение обычной карточки их не сбрасывает.

`npm run preview` также создаёт `preview-deposits.html`. В демо март: три пополнения, август: три, сентябрь: одно, октябрь: ни одного. Это вымышленные данные; рабочая база не затрагивается.

## Темы

Справа сверху переключаются светлая и тёмная темы. По умолчанию светлая; выбор хранится в браузере (`classroom.theme`), независимо от журнала и аккаунта. При блокировке хранилища переключение работает до перезагрузки. Тема не меняет записи и не требует обновления SQL.

## Отсутствие по умолчанию (локальная версия до одобрения)

Неотмеченный ученик считается отсутствующим на сегодняшней или прошедшей лекции/практике, если это занятие есть в расписании на выбранную дату и ученик уже присоединился. Ручные отметки «Присутствует» и «Уважительная» имеют приоритет. Будущие занятия, выходные, снятые с расписания типы и прежние отметки без типа не получают автоматических пропусков.

Это правило отображения и статистики, а не фоновая массовая запись в SQL. В базе и резервной копии хранятся ручные отметки; значения по умолчанию вычисляются при открытии журнала по текущей локальной дате устройства. Открытая страница пересчитывает их при наступлении нового дня и возвращении во вкладку. Обновлять SQL для этой функции не требуется.

В `preview-attendance.html` демо-дата зафиксирована на 27.03.2027, чтобы можно было проверить разные дни без ожидания. Просмотр не меняет рабочую базу.
